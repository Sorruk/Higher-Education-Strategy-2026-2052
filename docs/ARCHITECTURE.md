# Архитектура и эксплуатация

## Данные

| Таблица | Содержимое |
|---|---|
| settings | Владелец первоначального запуска, состояние импорта |
| members | Email, отображаемое имя, роль |
| organizations | Двуязычный реестр вузов, ведомств, подразделений и партнёров |
| documents | Файл, SHA-256, размер, статус источника, адрес R2 или части исходника |
| actions | Мероприятие, год, исполнитель, срок, статус, прогресс, подтверждение |
| indicators | Паспорт показателя, единица, ссылка на исходный пункт |
| targets | Уникальная пара показатель + год, текстовая цель |
| observations | Уникальная тройка показатель + год + уровень, числовой факт, доказательство |
| reports | Отчёт, автор, согласование и комментарий проверяющего |
| audit | Неизменяемая через интерфейс история операций |

Факты по организациям не суммируются автоматически в национальные: доли и показатели охвата требуют согласованной методики и знаменателей. Процент достижения не считается для «Hemmesi», прочерка, отсутствующего или нулевого плана. Неизвестный статус не считается доказательством просрочки. Прогресс мероприятия и достижение показателя — разные сущности.

Обновления используют `version` и возвращают HTTP 409 при устаревшей форме. Изменения показателя, его целей и аудита выполняются одним D1 batch. Мероприятия архивируются с возможностью восстановления. Внешние ключи проверяются сервером и схемой БД.

## Права

- Администратор: все реестры, цели, роли, рассмотрение отчётов, подтверждение сверки источника.
- Исполнитель: мероприятия, факты, организации, файлы, собственные отчёты. Отправленный отчёт закрыт для редактирования до возврата.
- Наблюдатель: чтение и выгрузка.

Роли общие для рабочего пространства; изоляция записей между организациями пока не реализована. Не предоставляйте доступ к общему пространству пользователям, которым нельзя видеть все его записи. Первый вход владельца выполняется за owner-only шлюзом Sites, после чего можно предоставлять доступ коллегам и назначать роли.

Вход, HTTPS и внешний контроль доступа выполняет Sites. Секреты не содержатся в клиентском JavaScript. API отвергает запросы без идентификатора пользователя; небезопасные cross-origin записи также отвергаются. При ином хостинге нужно заменить доверие к заголовкам полноценной проверкой сессии или токена.

## Файлы и экспорт

Оригиналы в R2 скачиваются как attachment с `nosniff`. Допускаются PDF, DOC/DOCX, XLSX/CSV, TXT, PNG/JPEG, M4A/MP3. Максимум загрузки через форму — 20 МБ. Встроенный антивирус и OCR отсутствуют. Аудио регистрируется как источник и не считается автоматически расшифрованным.

CSV экранирует формулы электронных таблиц. JSON выгружает текущие реестры и последние 250 операций, а не полный архив файлов или полную резервную копию БД. Для резервного копирования всей рабочей базы и R2 используйте средства владельца хостинга. Автоматическое восстановление из JSON в интерфейсе не реализовано.

## Контроль качества

Перед запуском эксплуатации заполните реальные организации и ответственных, сверьте импортированные проектные мероприятия с утверждённым приложением, согласуйте методики показателей и внесите документально подтверждённые факты. Интерфейс не делает юридических выводов о действительности документа по имени файла.

Уведомления по email, интеграции с кадровыми/учётными системами, электронная подпись, расписание резервного копирования и отдельные кабинеты с изоляцией по вузу не реализованы. Их нельзя считать включёнными в текущую версию.
