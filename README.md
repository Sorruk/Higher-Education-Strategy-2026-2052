# Strategiýa 2052 — платформа стратегии высшего образования

Двуязычная веб-система (русский / туркменский) для планирования и контроля реализации стратегии 2026–2052. Приложение сохраняет данные в серверной SQL-базе Cloudflare D1 и файлы в R2. Переключение языка — единственное прикладное значение в localStorage; рабочие реестры хранятся на сервере.

## Реализовано

- Обзор реализации, полнота сведений, направления работы и переход к проблемным записям.
- Реестр мероприятий по годам 2026–2052: исполнители, организации, сроки, прогресс, источники, приоритеты, архив и восстановление.
- Паспорт показателя, цели по годам, отдельные факты национального уровня и организаций. Ноль отличается от отсутствующего значения; «все» и прочерк не превращаются в числа.
- Реестр организаций с названиями на двух языках.
- Реестр источников, загрузка файлов до 20 МБ в R2, скачивание, SHA-256. Более крупные исходники частной версии разбиты на части и собираются без изменения байтов.
- Полугодовые и годовые отчёты: черновик → согласование → принятие / доработка. Приложения и комментарий проверяющего.
- Реестр направлений Стратегии: положения, извлечённые из текста по главам, с состоянием, связью с мероприятием и ссылкой на источник. Отвечает на вопрос «куда движемся», тогда как мероприятия отвечают «что делаем в этом году».
- Серверные роли: администратор, исполнитель, наблюдатель.
- Журнал изменений с автором, временем, значениями до и после. Защита от потери параллельных изменений через версии записей.
- Выгрузка CSV, JSON и печатная версия отчётов; адаптивный интерфейс.

## Репозиторий и рабочие данные

Этот GitHub-репозиторий содержит **код платформы**, миграции и тесты. Исходные документы пользователя, аудио и рабочие отчёты не должны попадать в публичный GitHub. Публичный вариант `lib/seed.json` содержит пустые массивы. После запуска организации, мероприятия, показатели и документы добавляются через интерфейс. Закрытая рабочая версия может использовать предварительно подготовленный импорт отдельно от публичного репозитория.

Направления Стратегии импортируются тем же закрытым путём: `private-data/seed.json` содержит ключ `directions` и заменяет `lib/seed.json` в закрытой сборке. Текст Стратегии в публичный репозиторий не попадает — в нём остаются пустые массивы. Рядом лежит `private-data/actions-appendix1.json`: 37 мероприятий, прочитанных напрямую из Word-файла приложения 1, с исполнителями, ожидаемыми результатами и сроками, выведенными из формулировок «möhleti». Этот файл не импортируется и служит для построчной сверки уже загруженных мероприятий.

Частная подготовленная версия использует 37 мероприятий из проекта плана 2026 года и 34 строки показателей (33 пункта, один с двумя видами аккредитации). Цели сверены с приложением 2 приказа №45 от 14.02.2026. Мероприятия требуют построчной сверки с приложением 1. Фактические результаты не заполнены вымышленными значениями. Русские краткие названия являются рабочим переводом. Контрольные даты интерпретируют указанный месяц/период как его конец; исходные сроки сохранены в карточках. Аудио из OneDrive не удалось прочитать, оно не расшифровано.

## Технологии

TypeScript, React 19, Vinext / Vite, Cloudflare Workers, D1 (SQLite), R2, Drizzle ORM для схем и миграций, Zod для проверки входных данных. Node.js 24 рекомендуется. Это серверное приложение, GitHub Pages для него не подходит.

## Локальный запуск

```bash
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_glamorous_dorian_gray.sql
npm run dev
```

Открыть `http://127.0.0.1:5173/`. Локальная имитация входа использует `seedy@sites.test`; в опубликованной сборке она отсутствует. Первый вошедший пользователь получает роль администратора **только при первоначальном запуске за закрытым шлюзом Sites**. Не открывайте доступ другим пользователям до завершения первоначального входа владельца.

Если сборка запускается в среде Codex с ограничениями на записи вне проекта, направьте `npm_config_cache` в доступную локальную папку. Для предпросмотра собранного Worker на macOS при необходимости используйте `XDG_CONFIG_HOME` в доступной папке и `CHOKIDAR_USEPOLLING=1`.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm start -- --port 8787
# В другом терминале; только для локальной тестовой базы:
npm run test:api
```

Интеграционные тесты работают только с localhost. Они создают помеченные `QA` записи в локальной базе. Не запускайте их против рабочей базы. Проверяются запрет анонимных записей и чтения, роли, переходы отчётов, валидация показателей, конкурентные изменения, аудит и точность скачивания из R2.

## Публикация

Поддерживаемый маршрут — Sites с закрытым доступом владельца. `.openai/hosting.json` объявляет `DB` и `BUCKET`; при регистрации закрытого сайта в нём сохраняется его `project_id`. Сборка создаёт Worker в `dist/server/index.js` и ресурсы в `dist/client/`. Sites применяет миграции из `drizzle/` и подключает D1 / R2.

Проверка пользователя основана на доверенных заголовках шлюза Sites. Не размещайте Worker напрямую в открытом интернете без адаптации аутентификации и удаления возможности подделать эти заголовки. Назначение роли в интерфейсе само по себе не приглашает пользователя: доступ к закрытому сайту предоставляется отдельно владельцем в настройках Sites.

## Структура

- `app/platform.tsx`, `app/globals.css` — двуязычный интерфейс.
- `app/api/strategy/route.ts` — чтение реестров и изменения с проверкой прав.
- `app/api/upload/route.ts`, `app/api/files/[id]/route.ts` — R2.
- `lib/server.ts`, `lib/domain.ts` — серверные операции, аудит, расчёты.
- `db/schema.ts`, `drizzle/` — 10 таблиц и миграция.
- `tests/` — проверки правил и API.
- `docs/ARCHITECTURE.md` — модель данных и эксплуатационные ограничения.

Изменять уже применённую миграцию нельзя. Новые изменения схемы: `npm run db:generate`, проверка SQL, затем новая публикация. Структура БД обновляется миграциями; исходные данные загружаются отдельно и не перезаписывают существующие записи.

## GitHub Actions

Готовый шаблон автопроверки находится в `docs/github-actions-ci.yml.example`. Чтобы активировать его, сохраните файл в `.github/workflows/ci.yml` через GitHub с правом изменения workflow. Текущий Git-доступ разрешает код, но не изменение workflow. Локальные проверки выполняются командами выше.
